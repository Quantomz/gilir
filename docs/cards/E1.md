# E1. Publish reviewed crop profiles and explicit evidence coverage

Owner: @yslee1106
Lane: Calculations and crop data
Estimated effort: 2 hours. This is an estimate, not a delivery guarantee.
Phase: core

## Outcome

The catalogue exposes only source-backed crop profiles and rules with documented applicability; unsupported coverage stays unavailable.

## Start immediately

Start from the [shared starter in PR #17](https://github.com/Quantomz/nefalos_nasa_hackathon/pull/17), branch `chore/parallel-build-baseline`. Use the checkout commands in its README. After that PR merges, new cards can branch from `main`.

Implementation prerequisites: None after the published shared baseline. Do not wait for another coding card.

Implement `readRegistryRelease` and `readCatalogue` from the frozen schemas. Use syntheticRegistryFixture to test parsing and selection without a weather backend. Source curation is implementation work against the existing parameter checklist, not a task to design new agronomy.

Read [AGENTS.md](https://github.com/Quantomz/nefalos_nasa_hackathon/blob/chore/parallel-build-baseline/AGENTS.md), activate pstack, and use the frozen [contracts](https://github.com/Quantomz/nefalos_nasa_hackathon/blob/chore/parallel-build-baseline/docs/contracts.md). The [specification](https://github.com/Quantomz/nefalos_nasa_hackathon/blob/chore/parallel-build-baseline/spec.md) owns product behavior.

## Implement

- [ ] Create the first immutable release with source-reviewed maize, common-bean dry-grain, and wheat profile records where the cited data supports them. Use the source tables linked below; record exact table/region/management and all assumptions. Never infer a faster cultivar just to fit.
- [ ] Fill fixed stage durations, Kc, turnaround basis, applicability/precedence, supported historical stage allocations, and preparation text. Unknown temperature rules stay unavailable. If a target profile lacks evidence, leave it unreleased and keep the criterion open.
- [ ] Implement stable applicability filtering and registry version lookup. Only released crop-purpose entries enter the catalogue. Real records cannot carry synthetic provenance.
- [ ] Publish no pest or weed rules or coverage manifests; they are outside the MVP (spec 3.4). `resolveRegistry` returns `pestCoverage` as unavailable until the contract amendment removes it. Release physical/regulatory sequence rules only when directly sourced.
- [ ] Validate numeric units, stage totals, source IDs, reviewed status, and coverage manifests. Preserve immutable old releases for frozen-job retries.
- [ ] Provide one documented farm/crop combination whose applicable released profile can support I2, and get a second person or independent review to compare the release with its source table.

## Done when

- [ ] Release fixtures validate and invalid units, missing source references, synthetic release data, and ambiguous precedence fail tests.
- [ ] The intended first crop records have traceable source comparisons. Missing records remain explicitly pending rather than invented or silently omitted.
- [ ] A documented supported farm/crop case has an applicable reviewed profile and complete parameter fields. Unsupported location/crop combinations return unavailable coverage. The observed live plan belongs to I2, not this component gate.

## Verification

Run `npx vitest run tests/engine/registry` plus `npm run check` and `npm run build`. Attach commands and observed results. A missing test file is not a passing check. Name fixture-based evidence explicitly. Put screenshots, logs, or source tables under `docs/evidence/E1/`. A peer reviews the exact PR.

Merged code and this card's evidence complete this component. I1, I2, and I3 separately gate the real assembled application.
