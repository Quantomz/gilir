# F4. Save drafts and results locally and download a readable PDF

Owner: @Quantomz
Lane: Frontend
Estimated effort: 2 hours. This is an estimate, not a delivery guarantee.
Phase: core

## Outcome

A farmer can reopen their saved inputs and results on the same device and download a readable PDF without an account.

## Start immediately

Start from the [shared starter in PR #17](https://github.com/Quantomz/nefalos_nasa_hackathon/pull/17), branch `chore/parallel-build-baseline`. Use the checkout commands in its README. After that PR merges, new cards can branch from `main`.

Implementation prerequisites: None after the published shared baseline. Do not wait for another coding card.

Implement the existing `localPlans` and `exportPdf(snapshot): Promise<Blob>` ports using completed snapshot fixtures. No server or frontend composition is required. Use IndexedDB through idb and pdf-lib already in the starter.

Read [AGENTS.md](https://github.com/Quantomz/nefalos_nasa_hackathon/blob/chore/parallel-build-baseline/AGENTS.md), activate pstack, and use the frozen [contracts](https://github.com/Quantomz/nefalos_nasa_hackathon/blob/chore/parallel-build-baseline/docs/contracts.md). The [specification](https://github.com/Quantomz/nefalos_nasa_hackathon/blob/chore/parallel-build-baseline/spec.md) owns product behavior.

## Implement

- [ ] Persist LocalState, including partial draft, page, active job capability, and completed snapshot. Validate restored snapshots, version the stored envelope, and distinguish unavailable storage from no saved state.
- [ ] Keep synthetic fixture storage separate from real farmer data. Clear removes local state; authorized transient server deletion is the caller responsibility.
- [ ] Generate an actual PDF Blob from the snapshot with location/coordinates, timeline, warnings, baseline/preparation, actual data period, sources, assumptions, and method versions.
- [ ] Paginate long details and avoid clipped crop labels. Use a suitable licensed font when needed and include its license. No remote request is required to read the exported file.
- [ ] Export saved no-plan results honestly as an insight/status report. Never insert a suggested calendar into an unavailable result.

## Done when

- [ ] A saved result remains readable after browser restart and after simulated server expiry. Draft and active-job restoration are covered.
- [ ] Storage quota/error and invalid old schema produce useful messages rather than silent loss or fabricated defaults.
- [ ] Actual PDFs from a plan, warning plan, and missing-data fixture open offline and are visually inspected for clipping, warnings, and source details.
