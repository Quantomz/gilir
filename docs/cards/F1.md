# F1. Build the five-page input flow and editable history

Owner: @Quantomz
Lane: Frontend
Estimated effort: 2 hours. This is an estimate, not a delivery guarantee.
Phase: core

## Outcome

A farmer can complete the five input steps, edit last year's crop bars, and submit a valid plan request without losing their inputs.

## Start immediately

Start from the [shared starter in PR #17](https://github.com/Quantomz/nefalos_nasa_hackathon/pull/17), branch `chore/parallel-build-baseline`. Use the checkout commands in its README. After that PR merges, new cards can branch from `main`.

Implementation prerequisites: None after the published shared baseline. Do not wait for another coding card.

Use `inputFixture`, `fixtureClient`, and `OnboardingProps`. F2 supplies a field picker behind its existing slot. Render that slot and test field input with a fixture until its implementation arrives. F3 supplies Results behind its existing slot. The public `PlannerClient` already supplies catalogue, submit, read, and remove.

Read [AGENTS.md](https://github.com/Quantomz/nefalos_nasa_hackathon/blob/chore/parallel-build-baseline/AGENTS.md), activate pstack, and use the frozen [contracts](https://github.com/Quantomz/nefalos_nasa_hackathon/blob/chore/parallel-build-baseline/docs/contracts.md). The [specification](https://github.com/Quantomz/nefalos_nasa_hackathon/blob/chore/parallel-build-baseline/spec.md) owns product behavior.

## Implement

- [ ] Implement `Onboarding` with location, crops, water, priority, and history/start-date pages in that order. One primary task per page.
- [ ] Add crop bars with drag/resize and keyboard/date controls for planting and harvest, approximate flags, unsupported historical crops, explicit fallow, and skipped history. Empty gaps remain unknown.
- [ ] Require distinct selected crop-purpose IDs and a field-available date. Use `farmInputSchema` at submission; show validation beside the relevant page. Never drop crops to satisfy a result.
- [ ] Poll through the injected client, show queued/fetching/calculating states, stop polling terminal jobs, and pass the completed snapshot to the result slot. Restore draft/job through the F4 port when present.
- [ ] Compose the prepared slots without changing their props. Keep content usable at 360px and desktop, with keyboard operation and 44px controls.

## Done when

- [ ] A fixture-backed browser run completes all five pages, resizes both crop endpoints, goes backward without data loss, skips history, and handles a rejected submission and failed JobState without a completed snapshot.
- [ ] The same form works with all three water choices and all four priorities. Water answer does not alter scientific inputs besides its declared field.
- [ ] A browser recording shows the input flow and focus order at phone and desktop widths.

## Verification
