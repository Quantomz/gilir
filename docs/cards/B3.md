# B3. Run the separate worker and wire real adapters

Owner: @kyusuku
Lane: Backend and data
Estimated effort: 2 hours. This is an estimate, not a delivery guarantee.
Phase: core

## Outcome

A separate worker claims a durable job, freezes its scientific inputs, and persists the correct terminal result through the prepared ports.

## Start immediately

Start from the [shared starter in PR #17](https://github.com/Quantomz/nefalos_nasa_hackathon/pull/17), branch `chore/parallel-build-baseline`. Use the checkout commands in its README. After that PR merges, new cards can branch from `main`.

Implementation prerequisites: None after the published shared baseline. Do not wait for another coding card.

Implement a `runWorkerOnce` function with injected JobStore, prepareClimate, registry reader, and calculate dependencies. Test it with in-memory port implementations and synthetic results while B1/B2/E cards are in progress. Their real modules are swapped at one composition entrypoint.

Read [AGENTS.md](https://github.com/Quantomz/nefalos_nasa_hackathon/blob/chore/parallel-build-baseline/AGENTS.md), activate pstack, and use the frozen [contracts](https://github.com/Quantomz/nefalos_nasa_hackathon/blob/chore/parallel-build-baseline/docs/contracts.md). The [specification](https://github.com/Quantomz/nefalos_nasa_hackathon/blob/chore/parallel-build-baseline/spec.md) owns product behavior.

## Implement

- [ ] Claim with a lease, renew during retrieval/calculation, and honor failed renewals. Do not publish after losing ownership. Freeze the normalized input, cutoff, registry versions, climate snapshots, and config before calculation.
- [ ] Retry a frozen run using the same immutable snapshots. Unavailable frozen data causes an explicit failure rather than a silent new data version.
- [ ] Call the synchronous deterministic engine outside an HTTP request. Atomically complete/fail the claimed job through JobStore. No fake queued success and no fixture import in production.
- [ ] Implement a persistent climate cache using the declared port and PostgreSQL. Keep cache migration files under a card-specific B3 migration prefix to avoid edits to B1 migrations.
- [ ] Add worker startup, graceful shutdown, expired-job cleanup, environment documentation, and a readiness check. Database URL and worker ID are configured by kyusuku.
- [ ] Map source outages to service errors and genuine missing scientific coverage to insufficient-data results. Complete all six agreed result states through JobStore without rewriting them. Actual HTTP delivery is verified in I1.

## Done when

- [ ] Injected-port tests cover happy completion, missing data, provider outage, loss of lease, crash/retry after freeze, and duplicate completion.
- [ ] The worker starts as a separate process. Injected-port lifecycle tests prove restart replay and rejection after lease loss. Real PostgreSQL composition and restart acceptance belong to I1; this component card does not wait for B1 to merge.
- [ ] Document concrete commands for web, migrations, worker, cleanup, and readiness. Real NASA+engine acceptance is I1/I2.
