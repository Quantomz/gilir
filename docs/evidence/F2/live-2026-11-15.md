# F2 live provider verification

On 15 November 2026, all 17 existing live F2 browser cases passed against real NASA GIBS and MapTiler services. Additional homepage inspection confirmed the globe, its rotation, satellite imagery, and field handles at phone and desktop widths. No provider response was mocked in these runs.

This verifies the component against live providers on localhost. It does not establish deployment, complete F2 attribution for a Free account, or complete I3's assembled farmer journey.

## Tested code and environment

The suite ran from `c170dbea4e99fd1f5bed2839e6c77a04475f270e`. Main `a0fba59e5d7e31b29a45662d34b5c8cb3f35eaae` contains the identical reviewed tree after PR #48's squash merge. No application or test source changed for this run.

The environment used Node 24.22.3, installed Google Chrome, and a fresh Next.js development server at `http://127.0.0.1:3318`. The public API key was loaded from ignored `.env.local` and allowed the local origin. The account's one-active-key limit does not require an upgrade. Local testing and production can use the same key sequentially after changing its origin restriction.

The suite used one browser worker and viewports of 360 by 740 and 1280 by 800 CSS pixels. Its last case disabled WebGL2 at 360 pixels. Traces, video, automatic failure screenshots, and HAR capture were disabled. The retained screenshots contain rendered pages only. The log contains no key or provider request URL.

## Commands and result

```sh
	F2_LIVE=1 PW_CHROMIUM='/Applications/Google Chrome.app/Contents/MacOS/Google Chrome' \
	  node --env-file=.env.local node_modules/playwright/cli.js test --config /path/to/playwright.live.config.mjs
```

The temporary configuration selected only `tests/frontend/location/live.spec.ts`, used port 3318, and set `reuseExistingServer: false`. Both the Playwright process and its server inherited the key. It supplied `extraHTTPHeaders: { Origin: "http://127.0.0.1:3318" }` for the suite's Node-side TileJSON requests, which otherwise have no origin. The key restriction remained enabled.

The existing suite returned `17 passed (1.3m)`. The [complete sanitized log](live-2026-11-15/live-run.log) names every case. Coverage includes real searches for Indramayu, Labasa, and Ushuaia, camera placement, globe interaction, field editing, typed corners, attribution text, satellite metadata, and the no-WebGL fallback. This suite uses the development fixture page. Production intentionally returns 404 for that route.

A separate preflight request with the local origin returned HTTP 200 for both geocoding and satellite TileJSON. Satellite metadata reported `maxzoom: 22`. The attribution text named MapTiler and OpenStreetMap contributors. These responses contained no explicit `tileSize`, and the suite's 256-pixel default matched the configured source.

## Visual and provider checks

The suite's Blue Marble screenshots still showed a regional satellite view after its rapid zoom clicks. Those screenshots alone did not prove the far-out globe assertion. A fresh browser check therefore opened the actual homepage with empty browser storage, inspected the initial globe, dragged it, submitted Indramayu, and marked a field. It ran at 360 by 800 and 1280 by 800 pixels against the same local server with real providers.

The [response counts](live-2026-11-15/provider-responses.json) count observed successful HTTP responses, not unique tiles, quota charges, or image quality. They do not record requests that produced no HTTP response. The screenshot inspection supplies the separate evidence that the images rendered.

## Activation remains pending

The current picker has linked text credits but no linked MapTiler logo. [MapTiler requires a linked logo for Free accounts](https://docs.maptiler.com/guides/map-design/attribution/add-attribution/). The existing live attribution case adds a note about the logo but does not assert its presence. The owner confirmed the Free plan after this run, so the linked-logo requirement blocks activation. Complete that F2 change before deployment and keep F2 open until it is verified.

Before deployment, remove the local allowed origin from the key and allow only `gilir-web-production.up.railway.app`. Rebuild the reviewed web image with `NEXT_PUBLIC_MAPTILER_KEY`, then verify the public `/` page separately. The current Railway web service remains pinned to `ec2ef2255ba76d6383d81dad43ff98a70584a850`; the user has staged the key variable, but this verification made no Railway configuration changes or deployment.
